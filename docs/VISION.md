# 图片与视觉工具（view_image）

机器人不仅能「看见」当前消息里的图片，还能在后续轮次按需回看**引用 / 合并消息**里的图片，
以及历史消息里已缓存的图片。实现分两层：入站时把图片缓存到本地，模型侧只拿到稳定的
`[图片 #id]` / `[引用图片 #id]` 标注；需要内容时再调用 `view_image` 工具。

- 代码：`internal/core/vision_parts.go`（附件展开、缓存、标注）、`internal/core/turn.go`
  （本轮多模态输入与历史标注）、`internal/tools/vision.go`（工具）、`internal/media`
  （下载与存储）。工具在 `internal/core/dispatcher.go` 注册。
- 开关：`vision_enabled`（默认 **true**）控制本轮多模态输入与 `view_image` 的下发；
  `vision_max_images`（默认 **2**）限制单条消息抓取 / 本轮内联的图片数；
  `media_max_bytes`（默认 **4 MB**）限制单个附件大小。
- 设置来源：全部走 `internal/settings`（后台「模型与提示词」/「接入与运维」），`.env` 不再参与。
- 相关决策：D-020（图片本地缓存 + 多模态）、D-049（引用 / 合并图片与按需视觉工具）。

> 本文描述 0.3.0 的行为。图片缓存本身是既有能力；v2 新增的是**引用 / 合并消息的图片入库**、
> **模型可见的图片 id 标注**与**按需调用的 `view_image`**。不启用视觉时，图片仍会在后台
> 时间线里正常显示，只是不进入模型。

## 1. 目标与非目标

### 目标

- **时间线不烂**：QQ 附件 URL 带会过期的 `rkey`，入站时抓回本地，历史消息里的图永久可见。
- **当前图片直接看**：本轮消息自带的图片以多模态输入发给模型，不需要额外一次工具调用。
- **引用 / 合并图片不漏**：这些附件不在顶层 `attachments` 里，必须展开 `msg_elements` 才能缓存；
  本轮不内联，但模型可以通过 `view_image` 按需查看。
- **按需付费**：历史图片不每轮重发；模型只在图片确实重要时调用工具，避免把整个相册塞进 prompt。
- **失败不阻断**：图片下载 / 存储 / 视觉模型任一失败，都只返回「图片不可用」文本，回复照常完成。

### 非目标

- **不做 OCR / 文档解析 / 视频理解**：只处理 `image/*`；语音、视频、文件只记录元数据。
- **不把图片写进会话正文**：标注只进入模型输入，数据库里的消息文本保持干净。
- **不做跨会话图片库**：工具按 `media_id` 读取本地缓存，但 id 只会在同一会话的模型输入里出现，
  不提供列表、搜索或跨会话枚举。
- **不替代人类状态推测**：`human_status_vision_model` 被复用为视觉模型，但
  `human_status_vision_enabled` 只控制 `analyze_image`，与 `view_image` 无关。

## 2. 图片来源与落库

入站消息解码后，dispatcher 把附件分两组交给 `media.Bundle.Ingest`：

| 来源 | 平台字段 | 缓存 | 模型标注 |
|---|---|---|---|
| 当前消息 | 顶层 `attachments` | 图片下载并缓存，其它类型只记元数据 | `[图片 #id]` |
| 引用消息 | `msg_elements[].attachments` | 同上 | `[引用图片 #id]` |
| 合并 / 转发消息 | `msg_elements` 里嵌套的 `msg_elements` | 深度优先递归展开后同上 | `[引用图片 #id]` |

细节：

- **只缓存图片字节**：`Kind=image` 或 `Content-Type: image/*` 的附件才下载；语音 / 视频 / 文件
  保留文件名、类型、大小等元数据，不落二进制。
- **内容寻址**：媒体 id 是图片字节的 **sha256**，同一张图重复上传只存一份。
- **去重**：同一条消息里相同 URL 只下载一次；当前消息与引用消息分开处理，以保留来源区别。
- **抓取边界**：只允许 QQ 的附件域名（`qq.com.cn` / `qq.com` / `qpic.cn` / `gtimg.cn`，
  仅 http/https），单文件超过 `media_max_bytes` 直接拒绝；下载 / 存储失败只记 WARN，
  消息照常落库，附件保留占位记录。
- **每条消息的图片上限**：抓取时按启动时读取的 `vision_max_images` 截断；超出的图片保留
  附件记录但不缓存字节（因此也没有 `media_id`，不会出现在标注里）。

## 3. 模型可见的图片标注

图片 id 以稳定文本标注追加在消息正文之后，**只进入模型输入，不写进数据库正文**：

```text
这张图里是什么？
[图片 #a1b2c3…]

刚才引用那张图呢？
[引用图片 #a1b2c3…]
```

- **当前消息** → `[图片 #id]`；**引用 / 合并消息** → `[引用图片 #id]`。
- 同一 `media_id` 在一行里只标一次；正文为空时只保留标注。
- **历史消息也会标**：每轮构建模型输入时，之前消息里已缓存的图片会被追加 `[图片 #id]`，
  模型因此知道「上一轮的图还能回看」。这是模型输入的副本，落库的历史消息不被修改。
- **视觉关闭时**：标注仍可能出现在模型输入里（它只是文本），但 `view_image` 不会下发、
  当前图片也不会内联；模型不应据此声称看过图。

## 4. 当前消息的多模态输入

- 当 `vision_enabled=true` 且媒体存储可用时，本轮**当前消息**的图片以
  `data:image/...;base64,...` 内联为 `image_url` part，最多 `vision_max_images` 张。
- **引用 / 合并图片不内联**：它们只通过 `view_image` 按需查看。原因是一段引用可能带多张图，
  全塞进本轮会让 token 随引用链增长，而大多数回复并不需要看引用图。
- **历史图片不重发**：后续轮次不会重复内联旧图；模型需要时调用工具。
- **多模态降级**：模型 / 网关不接受图片时，自动退回纯文本重试一次（正文与图片 id 标注仍在），
  不会因为端点不支持图片而丢掉整条回复。

## 5. `view_image` 工具契约

工具定义（只在 `vision_enabled` 且工具开启时下发给模型）：

| 参数 | 必填 | 说明 |
|---|---|---|
| `media_id` | 是 | 消息里 `[图片 #id]` / `[引用图片 #id]` 给出的图片 id |
| `question` | 否 | 想从图片里确认的具体问题；最多 **200** rune |

- **返回**：一段纯文本描述，最多 **500** rune。没有「成功 / 失败」结构化字段，失败也是文本。
- **实现**：读取本地缓存 → 校验 `image/*` → 调视觉模型（`temperature=0.2`、
  `max_tokens=500`、超时 **45s**）→ 截断结果。默认提示词要求客观描述画面、场景、
  可见文字与关键细节，**不推断年龄、性别、健康等敏感属性**。
- **风险级别**：只读（`ReadOnly`），不需要管理员身份；与 `run_shell` 等危险工具无关。
- **模型**：优先 `human_status_vision_model`；为空时回退主模型 `model`；两者都为空返回
  「图片不可用：未配置视觉模型。」
- **不会**：逐图自动调用、列出可用图片、跨会话查找、生成或修改图片。

## 6. 开关、模型与下发条件

| 条件 | 当前图片内联 | 图片标注 | `view_image` 下发 | 工具调用结果 |
|---|---|---|---|---|
| `vision_enabled=true` + 工具开启 | ✅（≤ `vision_max_images`） | ✅ | ✅ | 正常描述或降级文本 |
| `vision_enabled=true` + 工具关闭 | ✅ | ✅ | ❌ | 模型无法调用 |
| `vision_enabled=false` | ❌ | 仍可能出现 | ❌ | 若被旧上下文诱导调用 → 「视觉能力未启用」文本 |

- `vision_enabled` 是**全局开关**，没有按群覆盖；`tools_enabled` / 按群 `tools` 关闭时
  整个工具集都不下发，`view_image` 也不例外。
- 工具注册发生在启动时（需要媒体存储与 AI 客户端）；开关判断在**每次调用**读取设置，
  因此后台切换 `vision_enabled` 不需要重启。
- 视觉模型与人类状态推测共用 `human_status_vision_model`：换模型只改一个键；
  `human_status_vision_enabled` 不会关闭 `view_image`，`vision_enabled` 也不会关闭
  `analyze_image`。

## 7. 失败降级

`view_image` 对下列情况都**返回文本、不返回 Go error**，工具调用在审计里仍算成功，
回复管线继续：

| 情况 | 返回文本 |
|---|---|
| 视觉未启用 | `图片不可用：视觉能力未启用。` |
| 参数不是合法 JSON | `图片不可用：工具参数无法解析。` |
| 缺少 `media_id` | `图片不可用：缺少 media_id。` |
| 媒体存储 / 视觉提供方未接线 | `图片不可用：媒体存储或视觉模型不可用。` |
| id 不存在或缓存已过期 | `图片不可用：图片不存在或已过期。` |
| 附件不是 `image/*` | `图片不可用：该附件不是图片。` |
| 未配置视觉模型（含主模型） | `图片不可用：未配置视觉模型。` |
| 视觉模型报错 / 超时 | `图片不可用：视觉模型调用失败。` |
| 模型返回空描述 | `图片不可用：视觉模型没有返回描述。` |

- **下载 / 存储失败不在这里**：那发生在入站，失败只记 WARN，消息仍正常落库与回复；
  最多导致这张图没有 `media_id`、模型看不到它。
- **多模态请求失败**有独立的降级路径（§4），与工具失败互不影响。
- 工具结果只在当前工具循环里交给模型，**不单独落库**；审计只记录工具名、`media_id` /
  `question`（截断 500 字）与耗时，不记录返回描述。

## 8. 成本

- **当前图片**：一次多模态请求本身就要付图片 token；上限 `vision_max_images`（默认 2），
  且只在本轮发送。
- **`view_image`**：每调用一次 = 一次额外的视觉模型请求（最多 500 输出 tokens，45s 超时）。
  它不会自动触发；系统提示词要求「只在图片对回答确实重要时调用，不要逐图调用」。
- **历史 / 引用图不内联**：避免每轮为旧图重复付 prompt token；需要时一次工具调用即可。
- **媒体存储**：按 sha256 去重，单文件 ≤ `media_max_bytes`（默认 4 MB）；过期且无消息引用的
  缓存会按 `history_ttl_hours`（默认 72 小时）清理。
- 工具自身的 token 计入该次请求的 usage；后台没有单独的 `view_image` 计数器，
  观测走工具调用审计（`/api/tool-calls`）与日志 `tool call`。

## 9. 隐私与安全

- **只抓 QQ 附件域名**，限制协议、单文件大小与每条消息图片数；不跟随任意 URL。
- **只在群 / 私聊自己的会话里使用**：图片 id 来自该会话消息的标注，工具按 id 读取本地缓存；
  不提供跨会话列表或搜索。id 是内容 sha256，不可从外部猜测枚举。
- **发去哪里**：当前图片内联与 `view_image` 都会把图片字节发给配置的**视觉模型端点**
  （复用 `human_status_vision_model`，可能是第三方网关）。启用前应确认该端点与数据合规要求。
- **不落图片描述**：工具结果只进入当前模型上下文；工具审计不存描述，会话消息正文也不加标注。
- **不推断敏感属性**：默认提示词只要求客观描述画面、场景、文字与细节，明确排除年龄、性别、健康等；
  模型仍可能自由发挥，管理员应把描述当参考而不是事实。
- **关闭即不发送**：`vision_enabled=false` 时当前图片不内联、工具不下发；已经缓存的图片仍留在
  本地数据库，按历史保留策略清理，不会自动删除。

## 10. 存储与清理

- 图片字节存在 `media` 表（SQLite `BLOB` / PostgreSQL `BYTEA`），按 sha256 内容寻址；
  后台通过 `GET /api/media/{id}` 提供缩略图 / 原图。
- 会话消息的 `attachments` JSON 保留 `media_id`、类型、尺寸、大小等元数据；消息正文不变。
- **清理**：维护任务按 `history_ttl_hours` 删除过期且不再被任何消息引用的媒体；
  仍被引用的旧图不会被提前删掉。
- **权限**：`/api/media/{id}` 与后台其他数据一样要求认证；没有公开的媒体列表。

## 11. 排障

| 现象 | 先看 |
|---|---|
| 当前图片模型没看到 | `vision_enabled` 是否开启；`vision_max_images` 是否被 0 / 很小值限制；图片是否下载失败（日志 `failed to cache an image attachment`）；端点是否因多模态失败触发了纯文本降级（WARN `multimodal request failed`） |
| 引用 / 合并图片没有 `[引用图片 #id]` | 平台事件是否真的把附件放在 `msg_elements`；图片是否超过 `media_max_bytes`；单条消息图片数是否超过启动时的 `vision_max_images`；日志里是否有下载失败 |
| 模型不调用 `view_image` | `vision_enabled` 与工具开关（全局 / 按群 `tools`）是否开启；系统提示词是否注入；模型是否认为图片不重要（这是预期行为） |
| 工具返回「图片不存在或已过期」 | id 是否来自当前会话的标注；缓存是否已被 `history_ttl_hours` 清理；消息是否还引用它 |
| 工具返回「视觉能力未启用」 | `vision_enabled` 是否在后端被关闭；这不会让回复失败，工具结果只是文本 |
| 视觉模型总失败 | `human_status_vision_model` 是否是可用的多模态模型；为空时主模型 `model` 是否支持图片；端点是否接受 `data:` URI；看 WARN / DEBUG 日志中的上游错误 |
| 图片描述很长 / 很贵 | 单次结果硬截断 500 rune；检查是否每轮都在对同一张图调用工具（系统提示词要求按需调用） |

## 12. 测试

| 层 | 覆盖 |
|---|---|
| 标注 | 当前 / 引用来源区分、重复 id 去重、空正文、历史消息副本不改原文、非图片附件不标 |
| 入站 | `QuotedAttachments` 展开引用与嵌套合并、同 URL 去重、单条消息图片上限、下载 / 存储失败保留占位 |
| 工具 | `media_id` 缺失、非图片类型、id 不存在、视觉未启用、未配置模型、视觉调用失败 / 空结果、问题截断、结果截断 |
| e2e | 当前图片可被工具查看、引用图片下一轮可查、历史标注存在、关闭视觉时回复仍成功且不发起视觉请求 |
| 降级 | 多模态请求失败退回纯文本一次，回复不丢 |

go vet ./...

## 13. 限制

- **只理解图片**：不做 OCR 结构化、PDF、视频、音频；语音只记录 ASR 文本元数据。
- **只认已缓存图片**：平台 URL 过期、下载失败、或启动时被条数上限截掉的图片没有可用 id。
- **描述可能不准**：视觉模型可能看错文字、漏掉细节或过度推断；工具结果不是事实来源。
- **不保证跨轮一致**：同一张图两次调用可能得到不同描述。
- **抓取上限的启动时快照**：单条消息的图片抓取数在启动时读取 `vision_max_images`；
  修改该值后，抓取上限要重启才更新，而本轮内联上限按当前设置即时生效。
- **不提供图片管理界面**：没有按会话浏览 / 删除单张图片的入口；清理只按历史保留策略。
- **模型端点决定能力**：文本模型不支持图片时只能走纯文本；`view_image` 也需要真正多模态的
  `human_status_vision_model`，否则会稳定返回「视觉模型调用失败」。
